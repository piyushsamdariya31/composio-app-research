3 · The agent

How the research ran, and where a human stepped in

A research loop: draft, check, read the docs, fix, audit. Each stage catches a different kind of mistake, and every change is logged with its reason and source.

  1. 1

    Draft from memory

    The model answers all 100 apps from the hint and what it already knows. Fast and cheap, then frozen as the baseline to measure against.

    Output100 draft rows
  2. 2

    Check the rules

    11 consistency rules catch contradictions. A partner-gated app can't be "ready", evidence must sit on the vendor's own domain, and when OAuth exists but isn't primary, the row must say why.

    Codeverify/validate.py
  3. 3

    Cross-check two independent sources

    Composio's own catalog (which auth each existing toolkit uses) and the official MCP Registry, where publishers prove they own the domain. Any disagreement flags the row for reading.

    Sources1,841 toolkits + MCP Registry
  4. 4

    Read the vendor's docs

    For every app, open the auth, pricing and MCP pages and correct any claim the page contradicts.

    Changed$loopB fields in $loopB_apps apps
  5. 5

    Audit in a real browser

    A seeded sample of 2 apps per category, plus every flagged row, read in a real browser. Each miss becomes a new rule, applied to all 100 rows.

    Changed$loopC fields in $loopC_apps apps · 3 new rules
  6. 6

    Fresh holdout

    8 apps no loop had touched, checked only after everything else was frozen. This is the honest accuracy estimate.

    Result$bfh / $bt fields correct

Where a human or a real browser was needed

    $human

What the agent code enforces

  • Evidence must be a page the agent opened. A submission citing a URL it never fetched is rejected and sent back for repair.
  • Closed answer sets. The output schema is the rubric, so auth, access and verdict can't be free text.
  • Repair, then escalate. A rule violation gets two repair attempts. After that the row is saved as low-confidence and routed to a human.
  • Composio-native tools. Search and page reading run through the Composio SDK (TAVILY_SEARCH, TAVILY_EXTRACT, FIRECRAWL_SCRAPE), with Claude as the model.
How this run was produced. For this submission, Claude acted as the research agent. It used web search, page fetch and a real browser, with this repo's rubric, rule checks and scorers. agent/research.py packages the same loop as a headless pipeline on Composio's SDK. It's unit-tested offline with a scripted model and needs a Composio key and an Anthropic key to run live.

Loops can also make things worse. Loop B moved Waterfall.io from "trial, ready" to "partner, blocked". The audit then set it to the correct "approval, friction". That's why the audit exists.

Rules the audit added, applied to all 100 rows

  • A free plan is not a free API. Read the plan table's API row. This changed Help Scout, Freshdesk and Smartsheet to trial.
  • A docs-search MCP is not an official MCP. It can't act on the account. This changed Twilio.
  • If OAuth exists but isn't primary, say why. This moved Netlify, Vercel, Supabase and Sentry to OAuth, and 17 apps now carry a written reason.

5 · Proof

Run it yourself

The repo holds the agent, the checks, the data from every pass, and a GitHub Action you can trigger.

Run the research agent

pip install -r requirements.txt
export COMPOSIO_API_KEY=...  ANTHROPIC_API_KEY=...
# connect Tavily or Firecrawl in Composio first
python -m agent.run --only 41          # one app
python -m agent.run --ids 1-100        # all 100
python -m verify.score agent_run       # grade it
Trigger: "Research one app"README

Check everything offline, no keys

python -m pytest -q              # 8 tests
python -m verify.validate final  # 11 rules
python -m verify.score           # every number
python page/build.py             # rebuild page
